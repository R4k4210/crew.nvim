concept · nvim plugin

Agents as workspaces, not splits

Each agent lives in its own full window workspace, the way Hyprland or AeroSpace treat desktops. Workspace 1 is your editor with neo-tree and bufferline untouched. Workspaces 2 to 9 are agents. The pills in lualine tell you which one is working, which one is waiting on you, and which one is done.

C-Space then jump editor ⇄ last agent picker new agent In the mockup, click the window and press the second key alone (Tab also toggles).

How it is built

Every workspace is a Neovim tabpage. Tab 1 keeps your layout. Each agent tab holds one terminal window that fills the screen, so Claude renders at full size and nothing fights for columns.

Bufferline turns into a context header inside agent tabs, showing profile, cwd and branch, while lualine stays the same everywhere and gains the workspace pills.

Knowing who needs you

Claude Code hooks (Notification, Stop, UserPromptSubmit) call nvim --server $NVIM --remote-expr to report state. The plugin colors the pill and pulses it when an agent waits on a permission prompt.

The same state could also be pushed to sketchybar, so the Mac bar shows it when Neovim is in the background.

Usage meters

Inside an agent workspace the header shows three bars. Context comes from that session, while the 5 hour and weekly limits belong to the profile, so claude and claude-work each show their own account.

Claude Code already sends context_window.used_percentage and rate_limits.five_hour / seven_day to its statusLine script. Ours just forwards that JSON to Neovim through $NVIM.

Proposed keys

One prefix that works in normal and terminal mode, like tmux. Letters such as jk stay free inside the terminal.

<C-Space><Space>editor ⇄ last agent <C-Space>1..9jump to workspace <C-Space>ppicker with live preview <C-Space>nnew agent (claude, claude-work) <C-Space>xclose agent workspace
